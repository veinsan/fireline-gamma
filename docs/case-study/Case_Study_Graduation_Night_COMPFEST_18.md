# FIRELINE: Platform Intelijen Risiko Kebakaran Hutan dan Lahan Berbasis AI untuk Pencegahan, Prioritas Respons, dan Perlindungan Masyarakat di Kalimantan

*Gambar 1. Karhutla Kutai Barat Meluas, 415,51 Hektare Hutan dan Lahan Terbakar.*

## Problem Description

Setiap musim kering, ancaman kebakaran hutan dan lahan (karhutla) di Kalimantan kembali bertransformasi menjadi krisis multidimensional yang masif. Berdasarkan pemantauan dan laporan penanggulangan bencana, eskalasi darurat ini terekam jelas dari lonjakan ribuan titik panas aktif, di mana lebih dari 1.842 titik api terdeteksi di seluruh wilayah Kalimantan, dengan puluhan ribu hektare lahan (seperti catatan luasan karhutla di Kalimantan Barat yang mencapai 28.680 hektare dan ratusan hektare di kawasan strategis Kalimantan Timur) hangus terbakar.

Karhutla di wilayah ini tidak pernah berdiri sendiri sebagai fenomena titik api spasial di peta kosong. Ia membakar ekosistem lahan gambut yang rentan di kedalaman, mengancam permukiman padat, fasilitas pendidikan, hingga infrastruktur vital. Dampaknya menjalar cepat, kabut asap pekat menurunkan kualitas udara hingga tingkat berbahaya yang melumpuhkan aktivitas ekonomi dan memaksa penutupan jalur penerbangan (seperti terganggunya operasional Bandara Singkawang akibat jarak pandang di bawah batas aman). Kondisi ini langsung memicu lonjakan kasus Infeksi Saluran Pernapasan Akut (ISPA) dan mengancam kesehatan jutaan jiwa penduduk lokal.

Di lapangan, tantangan terbesar bagi command center, pemerintah daerah, dan *Non-Governmental Organization* (NGO) bukanlah ketiadaan data, melainkan fragmentasi informasi yang parah. Saat ini, data cuaca dari BMKG, titik panas aktif (*active fire*) dari NASA FIRMS, peta tutupan lahan dari ESA WorldCover, serta batas administrasi dan sebaran infrastruktur vital terisolasi di dalam platform yang berjalan dependen. Kondisi ini memicu rantai inefisiensi yang membahayakan keselamatan publik karena satu titik panas dengan intensitas kecil di dekat fasilitas kesehatan atau desa dengan kepadatan tinggi sering kali jauh lebih mematikan dibanding titik api besar di lahan terbuka tanpa penghuni. Tanpa korelasi data spasial yang terintegrasi, petugas rentan salah menetapkan prioritas. Selain itu, dengan ribuan titik panas yang muncul secara simultan dan ditangani oleh personel gabungan yang terbatas, petugas lapangan sering kali harus bekerja secara buta tanpa arahan yang jelas. Tanpa integrasi data yang cepat, rata-rata waktu verifikasi lapangan memakan waktu hingga 12–24 jam, sementara laporan masyarakat sering kali terlambat berjam-jam dari waktu kemunculan api pertama di satelit. Pada saat yang sama, informasi publik yang diterima masyarakat berjalan sangat lambat dan pasif. Warga di desa-desa terpencil atau dekat kawasan gambut kerap baru menyadari bahaya ketika asap sudah pekat dan mengganggu aktivitas, karena tidak adanya sistem peringatan dini yang kontekstual, transparan, dan mudah dipahami.

Keterlambatan verifikasi, buta informasi operasional, dan lambatnya respons dalam situasi karhutla berarti perbedaan antara pencegahan dini dan bencana kemanusiaan yang tidak terkendali. Para pemangku kepentingan membutuhkan lebih dari sekadar peta titik api mentah atau dashboard pantauan pasif.

Mereka membutuhkan sebuah platform decision-support berbasis *Artificial Intelligence* dan integrasi data spasial yang mampu mengubah sinyal data yang terpecah-pecah menjadi pemahaman yang *actionable*. FIRELINE hadir untuk menjawab pertanyaan kritis secara presisi, area mana yang paling mendesak untuk diselamatkan, siapa populasi yang paling rentan terpapar, laporan mana yang harus diverifikasi lebih dulu, dan respons apa yang harus diprioritaskan pertama kali untuk melindungi keselamatan masyarakat Kalimantan secara akurat dan berdampak nyata.

# Problem Identification

Dalam merancang platform intelijen risiko karhutla, dibutuhkan pemahaman mendalam terhadap kondisi nyata di bentang alam Kalimantan. Ahli Data Science diharapkan memanfaatkan dataset utama dan dataset pendukung untuk mengidentifikasi masalah, menganalisis data, serta menemukan *insight* yang relevan.

### a. Analisis Dataset

Lakukan analisis menggunakan **NASA FIRMS Active Fire Data** yang telah disediakan sebagai dataset utama yang memuat informasi *latitude, longitude, acq_date, acq_time, satellite, confidence, brightness/bright_ti4, frp, scan, track, instrument, version,* dan *daynight* yang dapat di akses melalui link berikut:

1. Fireline_hotspot_kalimantan_viirs_noaa20_2024_2026.csv

Peserta diwajibkan memilih **minimal satu** dataset pendukung dari link-link berikut ini:

1. BMKG - Weather Data
2. Climate Data Daily IDN
3. Indonesian province maps with population

5. Pontianak Weather Daily 2021-2024
6. Forest Fires Dataset

Visualisasikan hasil analisis dalam bentuk dashboard (Tableau, Looker Studio, atau Power BI) yang mencakup tren hotspot, peta, filter wilayah/waktu, dan visual *exposure*. Untuk memaksimalkan insight yang ingin diperoleh, Anda **didorong untuk mencari dan menggunakan dataset lain yang lebih relevan** sebagai dataset pendukung.

# Implementation & System Design

Rancang rencana pengembangan yang terstruktur, baik dari sisi strategi produk maupun rancangan teknis sistem.

### a. Tentukan *goals* dan *success metrics* dari produk Anda.

Tentukan *goals, success metrics, background, product scope, user requirements* (stakeholders, user stories, acceptance criteria), *functional & non-functional requirements*, serta *key milestones*.

**Hint:** Silakan menggunakan template PRD berikut.

### b. Buat *Product Prioritization & Roadmap*.

Lampirkan **Product Requirement Document (PRD)** untuk memperjelas detail fitur dan menjadi dokumen acuan bagi para tim dalam pengimplementasian produk. Susun matriks prioritas dan peta jalan pengembangan (*roadmap*) yang terstruktur.

**Hint:** Kalian dapat menggunakan *prioritization framework*, seperti RICE, MoSCoW, *Value Effort Matrix*, dll. Silakan gunakan template berikut: Value Effort Matrix, PRD

### c. Buatlah Use Case Diagram, ERD, dan System Design.

Ahli Software Engineering dapat membuat *use case diagram* yang terkait dengan fitur-fitur yang tertera pada PRD, membuat hubungan antar data yang diperlukan dalam pembuatan ERD, dan buat *blueprint architecture* aplikasi dengan System Design. Anda **dibebaskan menggunakan tools apapun** untuk membuat diagram.

- *Use Case Diagram*
  - Tampilkan aktor yang berinteraksi dengan sistem. (e.g: User, Admin, Service Provider, etc)
  - Tampilkan use case aktor dengan fitur dalam sistem. (e.g: User -> melihat lowongan pekerjaan)
  - Cantumkan jenis relasi (include/extend). (e.g: Edit profile <<include>> Login <<include>> Register)
  - Ekspektasi output dalam bentuk **UML Diagram**.

- *Entity Relationship Diagram*
  - Identifikasi *entity* dan atributnya dalam bentuk skema. Spesifikasikan tipe data untuk setiap atribut.
  - Definisikan Primary Key dan Foreign Key pada atribut yang relevan.
  - Gambarkan kardinalitas antar *entity* dengan jelas. (e.g: 1-1, 1-N, M-N)

- *System Design*
  - Definisikan tech stack dalam pembuatan sistem per layer. (e.g: Frontend -> React; Backend -> NestJs; Database -> Postgresql; etc)
  - Gambarkan Architecture Flow High-level System. (e.g: Client -> API Gateway -> Services -> etc.)

### d. Rancanglah Go-To-Market Strategy & Ethics

Rancang strategi adopsi produk yang komprehensif mencakup target audiens, kanal distribusi, strategi *onboarding, positioning*, pendekatan pemasaran, serta mitigasi risiko etis (seperti perlindungan privasi data warga, pencegahan *false alarm*, dan moderasi laporan masyarakat).
